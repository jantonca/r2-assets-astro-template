# r2-assets-astro-template — AGENTS.md

## Purpose

Reusable Cloudflare R2 asset-processing and delivery template for Astro
projects. This repository is a template, not a complete Astro application.
Changes must remain portable to multiple consuming repositories.

## Package and commands

The executable package lives in `lib/assets/` and uses pnpm 11. Run checks from
that directory:

- Install: `pnpm install --frozen-lockfile`
- Syntax: `pnpm run check:syntax`
- Unit tests: `pnpm run test:unit`
- Dependency audit: `pnpm run audit:deps`
- Full check: `pnpm run check`

Do not run credentialed R2 sync/status commands unless the user explicitly asks
for live bucket operations. Tests must use mocked R2 bindings.

## Architecture constraints

- `assets.config.js` is the public processor contract. `rules[].outputs` is the
  single authority for generated formats.
- Stable R2 keys are overwritten, so worker responses must not use
  `Cache-Control: immutable` unless filenames become content-addressed.
- Both worker patterns share `workers/r2-response.js`; keep cache, metadata, and
  content-type behavior centralized there.
- The Astro component defaults in `src/config/r2-images.ts` must match the
  formats generated by `assets.config.js`.
- Preserve relative R2 keys with POSIX separators for cross-platform consumers.
- Never read or commit `.env` / `.dev.vars` credentials.

## Verification

For processor or worker changes, require syntax checks, unit tests, dependency
audit, a Sharp conversion smoke test, and Wrangler dry-runs for both worker
patterns in a disposable consumer fixture. Component changes also need an Astro
build in a consuming project before rollout.
